ACME, expiry alerts and CRL monitoring. For the ADCS you already run.

If you run Active Directory Certificate Services (ADCS) with a small team, certificate renewals tend to live in scripts and calendar reminders. Ducks in a Row is one Windows service in front of the ADCS certificate authority you already run. Your machines, domain joined or not, request and renew their own certificates from it with a standard ACME client.

Features

What you get

  • Expiry alerts, free

    Email and webhook alerts for every certificate in your CA's inventory.

  • Pull, not push

    Each machine asks for its own certificate, so no credentials for your servers are stored anywhere and Ducks in a Row needs no rights on them.

  • One scoped credential per team

    You set the names a team may request with an external account binding credential, and the team serves itself within them.

  • Your trust chain stays as it is

    Certificates come from the ADCS you already run and chain to the root you already trust.

  • Rights checked before first use

    The setup wizard proves what it can of the service's rights on your CA, and says plainly what it cannot.

  • Kubernetes too

    cert-manager's built in ACME issuer works with it, with no plugin in the cluster. The Kubernetes chapter says which parts our tests have run.

CRL monitoring

The CRL nobody has in a calendar

A certificate that expires breaks one service. A certificate revocation list that expires breaks revocation checking for everything its CA ever signed, all at once, and for an offline root nothing automatic replaces it.

Ducks in a Row watches every CRL in the chain of the CA you connect it to, the offline root's included. It reads them from the CA itself and from the distribution points over LDAP and HTTP, and it watches each copy separately: a root CRL renewed into the directory but never copied to the web server is reported, with the location named.

Warnings for a CRL published by hand

  1. 30days
  2. 14days
  3. 7days
  4. 1day

A CRL published by hand gets warnings 30, 14, 7 and 1 days before it expires, by default. A CRL your CA replaces on a timer stays quiet unless the CA misses its own schedule, and warns again if it expires. The warnings go out by email and webhook, like certificate expiry, and they are part of the free core.

How it works

Three steps to the first certificate

  1. Ask for the rights first

    One page lists every right and firewall opening the server needs, ready to forward to your AD and CA team. The approvals are usually the lead time.

  2. Install the signed setup

    It carries its own runtime, so a server with no internet access installs from the one file. Windows SmartScreen may still warn about a new release while the certificate builds a reputation, so check the download before you run it.

  3. Point your ACME clients at it

    The client guide covers certbot, win-acme, Caddy, Traefik, Posh-ACME and cert-manager, with the directory URL and the challenge types.

Privacy

No telemetry. Ever.

Ducks in a Row runs entirely on your own servers and never sends data back to us or to anyone else. Fonts and other assets are bundled with the app, so the dashboard makes no third party requests. A tool that sits in front of your certificate authority should not be watching you, and this one does not.
